# FingerRoll

지문 기반 야간자율학습 출석 프로젝트. **초기 버전은 시간 제한 없이 학생별 하루 한 건의 출석을 기록**하고, 1교시 시작 시각으로 지각을 판정한다. 개발 목표 기간은 **2026년 11월~2027년 1월 초**이며, 아래 일정은 계획이지 완성 성과가 아니다.

**FingerRoll은 RoboMetrics와 별개의 프로젝트다.** RoboMetrics의 하위 프로젝트나 새 이름이 아니다. 이전 AI 준비 문서에서 두 이름을 묶은 표기는 잘못된 것이며 바로잡았다. 반입된 경로 탐색 코드는 다른 프로젝트에서 온 참고 자료일 뿐 FingerRoll의 구현이나 성과에 포함하지 않는다.

## 현재 확인 상태 — 2026-11-18 KST

- 이 작업 폴더는 시작 시 비어 있었다. 기존 학생 출석 구현은 확인되지 않았다.
- 원본 Handoff v2와 Starter ZIP을 로컬에서 찾았다. 두 자료는 **A* / Greedy / Dijkstra 격자 경로 탐색 프로젝트**를 설명한다. 출석 시스템의 기존 구현으로 취급하지 않는다.
- 인접한 기존 RoboMetrics 작업 폴더는 경로 탐색·로봇 실험 프로젝트다. 이번 저장소로 그 성과를 옮겨 주장하지 않는다.
- 기존 GitHub `J0hns0n-K/fingerprint-sensor-EC`는 공개 저장소이며 `README.md` 한 파일과 초기 커밋만 확인됐다. 해당 저장소는 변경하지 않는다.
- 새 저장소 [J0hns0n-K/junmo-sion-FingerRoll](https://github.com/J0hns0n-K/junmo-sion-FingerRoll)을 **Private**로 생성하고 로컬 `main`과 연결했다. 연결·검증 근거는 [킥오프 기록](docs/KICKOFF_STATUS.md)에 기록한다.
- 이번 준비 문서와 검증 작업의 수행자는 **AI assistant**다. 학생 구현, 센서 측정, 학교 배포 및 성능 개선은 아직 검증되지 않았다.

## 목표 동작

지문 센서가 학생을 확인하면 **한국 시간의 해당 날짜에 출석 기록 한 건**을 만든다. **18:25 정각까지는 정상 출석, 그 이후는 지각 여부 확인 대상**이다. **외출에서 돌아와 바로 출석한 것으로 확인되면 지각에서 제외**한다. 같은 날 다시 찍어도 최초 인식 시각을 유지하고 추가 출석을 만들지 않는다. 담당자가 사유를 확인해 상태를 바꿀 때에는 변경 이력을 남긴다. 출석 기록이 없는 학생은 **미확인**으로 두고 학생들이나 사감 선생님을 통해 상황을 파악한다. 외출 중인 학생을 자동 결석 처리하지 않는다. 담당자는 날짜별 명단을 조회하며, 알림은 확인·승인 후 최소 정보로 전달한다. **2·3교시별 추가 출석 의무·미출석 알림은 없다.**

사용자가 제공한 교시 시각은 **1교시 18:25~19:20, 2교시 19:30~20:20, 3교시 20:30~21:20**이다(`Asia/Seoul`). **18:10 접수 시작 제한은 폐기했다.** 하루는 한국 시간 00:00부터 다음 날 00:00 직전까지이며 어느 시각이든 그날의 첫 출석을 기록할 수 있다. **18:25에 바로 미확인 명단을 확인**하며 이후 인식·사유 확인에 따라 갱신한다. 외출 이외에도 **사용자에게 따로 사유를 알려준 학생**을 예외 확인 대상으로 다룬다. 사유 확인은 출석 완료와 별도로 기록한다. 2·3교시 시각은 참고 시간표로만 보존한다. 운영 날짜·요일과 최종 알림 검토·전송 시점은 미정이다. 지문 수집·실제 알림 전송은 준비 완료 상태가 아니다.

**장치 현황(2026-11-17 갱신):** 사용자가 구매를 보고한 상품은 **AS608 센서, F-F 점퍼선, microSD 카드, Raspberry Pi Zero 2 W(with Headers)**로 식별했으나, 이후 **라즈베리파이 주문 취소**를 알려주었다. 해당 보드는 준비된 장비에서 제외하며 사용할 중심 보드는 미정이다. [부품 목록과 확인 범위](docs/HARDWARE_INVENTORY.md). 센서 실물 사양·핀 배치·전원·통신·부팅·인식 동작은 아직 확인하지 않았다. 학생의 출석 판정 과제는 노트북에서 가상 데이터로 먼저 진행할 수 있다.

## 현재 구현 — 노트북 가상 출석 화면

[로컬 출석 저장 모듈](src/daily-attendance.mjs)과 브라우저 데모를 AI가 구현했다. 한국 날짜·가명 학생 ID별 최초 기록 한 건, 재인식 시 최초 시각 유지, 18:25부터 미확인 구분, 사유 확인과 실제 출석의 분리, 명시적 지각 면제·취소 이력을 확인할 수 있다. **현재 전체 132개 테스트 통과, 실패 0개**이며 별도로 브라우저 동작을 AI가 확인했다. [현재 검사·소스 해시](evidence/laptop-ui-01/result.json), [화면 사용법·한계](docs/LOCAL_DEMO.md), [명단·사유 API](docs/ROSTER_REVIEW.md).

작업 폴더에서 `node scripts/demo-web.mjs`를 실행하고 `http://127.0.0.1:4318`을 열면 가상 학생 네 명의 화면을 사용할 수 있다. 가상 시계는 2026-11-18 18:24부터 흐르며 매초 명단을 갱신한다. 실제 현재 시각이나 센서 인식이 아니며 서버 종료 시 화면 데모 기록은 사라진다. 이 노트북에서만 접속하도록 제한했고, 학교 운영용 로그인·권한·센서·실제 알림은 아직 없다.

`node scripts/demo-attendance.mjs`는 별도의 파일 저장 데모, `node scripts/demo-roster.mjs`는 메모리 명단 데모다. 파일형 데모 데이터베이스는 Git에서 제외된 `local/`에 남는다. 화면 데모는 그 파일을 읽거나 바꾸지 않는다. 실제 학생·지문·상세 사유는 모든 데모에서 사용하지 않는다.

## 첫 학생 과제와 시각 비교 이력

[Task 001A — 단일 교시의 정각·지각 경계 판정](docs/tasks/TASK_001A.md)은 안내 연습에서 시작했고, 이후 사용자의 AI 구현 요청에 따라 [시각 비교 함수](practice/task-001a.mjs)의 타입·시간대·달력 검증을 AI가 보완했다. [입력 형식과 범위](docs/TIMESTAMP_INPUT.md). 이전 안내 연습 소스와 [9개 사례 기록](evidence/task-001a-guided-03/result.json)은 보존한다. 현재 기능과 검사는 AI 작성으로 구분하며 학생의 독립 구현이나 전체 출석 시스템 완성으로 계산하지 않는다.

현재 아래 기존 [3개 테스트](practice/task-001a.test.mjs)와 추가 [입력 검증 테스트](practice/task-001a.validation.test.mjs)를 합쳐 **67개 통과, 실패 0개**다. [현재 결과와 소스 해시](evidence/task-001a-strict-input-01/result.json). 별도 설치는 필요 없다.

| 인식 시각 | 예상·실제 결과 | 기여 구분 |
|---|---|---|
| 18:20 | false | AI 안내 코드와 사례를 학생이 입력·수정 |
| 18:26 | true | 시각·예상값은 사용자 선택, 코드 안내는 AI, 입력은 학생 |
| 18:25 정각 | false | 사용자의 명시적 요청으로 AI가 직접 추가 |

실행 확인은 모두 AI가 수행했다. true는 사유 확인 필요를 의미하며 최종 지각 확정이 아니다. 67개에는 기존 3개가 포함되며, 앞선 9개 진단과도 겹치므로 과거 검사 수를 누적해 독립 사례 수로 주장하지 않는다.
