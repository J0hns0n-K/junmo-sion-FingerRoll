# 일정, Engineering Report와 Early EC 증빙

AI 작성 준비 문서. 기준일은 **2026-11-16 KST**다. 학생 구현·센서 성능·학교 도입 성과는 아직 검증되지 않았다. 아래는 계획이며 실제 결과가 생기면 갱신한다.

현재 사용자 결정에 따라 초기 구현은 **시각 제한 없이 한국 날짜별 하루 한 건 출석**하는 범위다. 지각 기준은 1교시 시작 18:25다. 2·3교시 반복 출석과 해당 교시 별도 미출석 알림은 초기 일정·성과 주장에서 제외한다.

사용자가 설명한 외출 예외를 포함한다. 외출 복귀 직후 출석은 확인 후 지각에서 제외하고, 기록이 없는 학생은 학생들이나 사감 선생님을 통한 상황 확인 전까지 미확인으로 둔다. 경계 비교 함수는 시각 기준 분류일 뿐 최종 지각·결석 판정의 완성 증거가 아니다.

개별 지원·제출 마감은 확인하지 않았다. 실제 제출일 이후 성과를 이전 제출 시점의 성과로 소급하지 않는다. 개발 목표 기간이 제출 가능 기간을 보장하지 않는다.

## 증거 보관 규칙

실험마다 ID, 질문/가설, 수행자, 실제 KST 시각, 구현 커밋 SHA, 입력/설정, 실행 명령, 예상 결과, 실제 출력, 실패·제외 건수, 결론·제한사항을 기록한다. 과거 출력은 덮어쓰지 않고 새 실험 ID로 남긴다. 개인정보 원자료는 저장소에 넣지 않고 승인된 별도 장소에 보관하며, Git에는 합성 데이터나 공개 가능한 집계·절차만 남긴다.

GitHub 계정·커밋 수는 학생 저자성의 충분한 증거가 아니다. 학생 자신의 설계 설명·편집·검증을 함께 확인한다. AI가 실행한 테스트, 학생이 실행했다고 보고한 테스트, 검토자가 재현한 테스트를 구분한다.

## Engineering Report 작성 틀

1. 문제와 사용자의 요구: 언제든 하루 한 건 출석, 18:25 기준 정상/지각, 날짜별 명단·예외, 최소 알림.
2. 초기 자료와 출처: 경로 탐색 Starter의 실제 범위, AI 참고 코드와 출석 구현의 관계.
3. 학생이 직접 정한 질문·설계 결정과 대안, AI가 제공한 부분.
4. 변경 내용과 커밋: 무엇을 왜 바꿨는지.
5. 검증 방법: 합성/실제 구분, 입력·환경·기대값·실행 명령·원자료.
6. 결과·실패·해석: Claim ID → 구현 SHA → 증거 파일 → 실제 수행자 → 제한사항.
7. 개인정보·동의·안전 설계와 통과하지 못한 운영 게이트.
8. 한계와 다음 실험. 미완료 기능·센서·배포를 완료로 표현하지 않음.

현재는 결과 보고서 대신 이 틀만 준비한다. Starter의 경로 탐색 테스트 통과를 출석 시스템 통과로 옮겨 적지 않는다.

## Early EC 초안의 사용 조건

현재는 학생 성과를 주장하는 완성 문안을 작성할 증거가 없다. 다음 문장은 **검증 후 채우는 내부 양식**이며 제출용 완성 문안이 아니다.

> [실제 기간] 동안 FingerRoll의 [학생이 직접 담당한 범위]를 수행했다. [완료한 기능]을 구현하고 [재현 가능한 검증]으로 확인했으며, [측정된 결과와 조건]을 기록했다. [미완료 범위와 한계]는 남아 있다.

검증된 모듈만 완성됐다면 그 모듈로 범위를 좁힌다. 근거 없는 지문 정확도, 학생 수, 시간 절감, 독자 알고리즘·발명, 학교 도입, 사생회 알림 운영을 쓰지 않는다. 상담·학생 검토 후 해당 지원서의 실제 형식과 길이에 맞춘다.
