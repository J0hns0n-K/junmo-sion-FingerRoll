# 미확인 명단과 사유 확인 — 로컬 합성 데이터 기능

구현·검사·실행: Codex AI assistant, 2026-11-18 KST. 개인 GitHub 계정으로 커밋해도 실제 코드 작성자는 AI다. 실제 학생·건강 정보·지문·학교 명단은 사용하지 않았다.

## 현재 가능한 일

`getRosterSummary({attendanceDate, expectedStudentIds, asOf})`가 전달받은 가명 학생 ID 명단과 실제 저장된 출석·확인 이력을 대조한다.

- 한국 시간 **18:25 직전까지** 기록 없는 학생은 `pending`(대기), **18:25 정각부터** `unconfirmed`(미확인)다. 조회로 결석 기록을 생성하지 않는다.
- 18:25는 출석 접수 마감이 아니다. 이후 처음 인식한 학생도 당일 출석으로 받고 다시 조회하면 명단에 반영한다.
- 사유는 확인됐지만 아직 지문 인식이 없으면 `reason_confirmed`(사유 확인·출석 미기록)다. 출석 완료 수에 포함하지 않는다.
- 늦은 첫 출석은 `review_required`다. 사유 확인 후 담당자가 별도로 지각 면제를 기록하면 조회 결과가 `excused`로 바뀐다. 원 출석 행·인식 시각은 수정하지 않는다.
- 이 API가 타이머나 화면을 자동 실행하는 것은 아니다. 호출자가 18:25와 이후 변경 때 다시 조회해야 한다. 후속 [노트북 가상 화면](LOCAL_DEMO.md)이 가상 시계·매초 조회와 버튼 작업을 연결한다. 실제 운영 스케줄러·인증은 미구현이다.

현재 명단은 호출할 때 제공하는 합성 ID 배열이며 등록 학생인지 확인하거나 학교 명단을 자동 수집하지 않는다. 중복·잘못된 ID는 거부하고 명단 밖 기록을 명단에 추가하지 않는다. `asOf`는 명시적인 시간대를 포함해야 하고 조회 날짜와 같은 한국 날짜여야 한다. 조회 시각보다 미래인 출석·확인 이벤트는 표시하지 않는다. 기기 시각을 인증하거나 실제 입력 시점을 재현하는 운영용 감사 기능은 아니다.

## 사유 확인과 변경 이력

`recordReview()`는 다음 세 작업을 별도 테이블에 추가한다. 기존 이력을 삭제·덮어쓰지 않는다.

| 작업 | 뜻 |
|---|---|
| `confirm_reason` | 사용자가 전달받은 사유를 확인. `reported_reason`, `outing`, `outing_return` 중 최소 구분만 기록 |
| `waive_lateness` | 늦은 출석이 이미 있고 사유도 확인된 경우 지각 면제. 확인 시각은 출석 시각 이후여야 함 |
| `clear_reason` | 사유 확인을 취소. 과거 이력은 보존하고 기존 면제도 재확인 상태로 돌림 |

새 사유를 확인하면 기존 면제는 자동 재사용하지 않는다. 사유가 확인됐다는 사실과 지각 면제 결정은 별개다. 출석 없는 학생이나 정상 출석에 면제 작업을 적용해 출석을 만들어낼 수 없다.

각 이력에는 날짜·가명 학생 ID·가명 확인자 ID·확인 시각·작업·최소 사유 구분·직전 이력 ID를 저장한다. 면제는 해당 최초 인식 시각과 연결한다. 상세 건강 증상, 상담 내용, 위치, 자유 서술 메모는 입력 항목으로 받지 않는다. 허용되지 않은 추가 필드는 거부한다.

수정 시 `expectedReviewId`에 화면에서 마지막으로 본 이력 번호(최초 0)를 전달해야 한다. 다른 요청이 먼저 변경했으면 `STALE_REVIEW`로 거부하고 최신 명단을 다시 확인하게 한다. SQLite 쓰기 트랜잭션으로 검증과 추가를 함께 처리한다. 과거 확인보다 앞선 시각의 새 이력도 거부한다. `listReviewHistory()`로 해당 날짜·학생의 이력을 볼 수 있다.

**확인자 ID는 기록용 값이며 로그인·권한 검증이 아니다.** 실제 운영 전에 담당자 인증·역할·시각 신뢰·접근 통제·보유기간·삭제 절차가 필요하다. 이 API는 로컬 합성 데이터 검증용이며 사감 선생님이나 학생에게 실제로 연락하지 않는다.

