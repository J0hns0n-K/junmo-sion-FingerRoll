# 노트북 가상 출석 화면

2026-11-18, 사용자 ‘계속’ 요청으로 AI가 구현·검사했고 2026-11-20 저장형 사용법을 정리했다. 가상 ID S001~S004만 사용한다. 실제 학생 정보·지문·메시지 전송은 없다. 화면과 검사는 학생 독립 구현으로 계산하지 않는다.

## 실행

Node.js가 있는 작업 폴더에서 다음을 실행한다. 추가 패키지 설치는 필요 없다. 확인 환경은 Node v24.22.1과 v24.22.3이다.

```powershell
node scripts/demo-web.mjs
```

브라우저에서 `http://127.0.0.1:4318`을 연다. 종료는 실행 창에서 `Ctrl+C`다. 포트가 이미 사용 중이면 시작에 실패하므로 기존 데모 실행 창을 먼저 확인한다. 이전 버전이 이미 실행 중이면 그 창에서 종료한 뒤 다시 실행해야 새 기능이 적용된다. 브라우저 검사는 별도 포트 4319와 별도 합성 저장 폴더를 사용했다.

새 연습의 시계는 **2026-11-18 18:24:00에서 시작하는 가상 시계**다. 실제 노트북 현재 시각이 아니며 실행 중 경과 시간만큼 진행한다. ‘시계 1분 앞으로’로 앞으로 이동할 수 있다. 날짜 변경 혼동을 피하려고 가상 날짜의 23:59:59.999에서 멈춘다. **다시 실행하면 출석·사유·면제 이력과 저장된 가상 시각을 복원**한다. 종료한 동안의 실제 시간은 더하지 않는다. 별도 파일 저장 데모의 SQLite 파일과 연결하지 않는다. 이전 메모리 전용 버전에서 종료해 사라진 기록을 복구하는 기능은 아니다.

## 저장과 새 연습

실행 위치와 관계없이 저장소의 `local/synthetic-web/`을 사용한다. `active.json`이 현재 가상 데이터베이스를 가리키고, 날짜·학생별 첫 출석·사유 변경 이력과 가상 시계 체크포인트는 해당 SQLite 파일에 저장한다. 조회·출석·확인·시계 이동 및 정상 종료 때 시계를 저장한다. 출석·확인 시각을 먼저 저장하고 이벤트를 기록해 재시작 뒤 시계가 이미 기록된 이벤트보다 과거로 돌아가지 않게 한다. 강제 종료 직전의 아직 저장되지 않은 경과 시간은 복원하지 않는다.

빈 명단에서 다시 연습하려면 현재 실행을 종료하고 다음을 실행한다.

```powershell
node scripts/demo-web.mjs --new-session
```

새 파일을 만들고 연결 파일을 교체한다. 이전 데이터베이스와 이전 연결 파일은 삭제하지 않는다. 새 서버 시작이 실패하면 현재 연결은 바꾸지 않는다. 잘못된 경로·손상된 연결 파일·지정 파일 누락은 오류로 중단하며 기존 기록을 임의 초기화하지 않는다. 브라우저는 연습 세션 변경을 감지하면 이전 사유 입력 창과 이력 표시를 해제한다. 이전 세션의 변경 요청은 409로 거부하므로 새 명단을 확인한 뒤 작업해야 한다.

`local/` 아래 저장 파일·연결 파일·백업 연결과 저널은 모두 Git에서 제외한다. 새 연습은 삭제·보유기간 정책을 구현한 것이 아니며 실제 학생 자료의 보관 수단으로 사용할 수 없다. 자동 검사의 `startDemoServer()` 기본값은 여전히 메모리 전용이고, 일반 실행 스크립트가 파일 저장을 명시적으로 연결한다.

## 확인 순서

1. 18:25 전에 S001의 ‘가상 출석’을 누른다. 정상 출석 한 건이 생긴다.
2. 시계를 1분 앞으로 옮긴다. 기록 없는 학생이 미확인으로 바뀐다. S001을 다시 눌러도 첫 시각과 상태를 유지한다.
3. S002의 ‘사유 확인’에서 ‘따로 전달받은 사유’를 기록한다. 사유 확인·출석 전으로 표시되며 출석 건수는 늘지 않는다.
4. S003을 늦게 가상 출석시킨다. 지각 여부 확인으로 남는다. ‘외출 복귀 직후 출석 확인’ 사유를 기록해도 자동 면제하지 않는다.
5. 담당자 역할의 사용자가 ‘지각 면제’를 누른 뒤 상태·원 인식 시각·이력을 확인한다. ‘사유 취소’는 다시 검토 상태로 돌리며 과거 이력을 보존한다.
6. S004는 미확인으로 남는다. 자동 결석·사생회 통보는 발생하지 않는다.

정상/지각 기준은 내부에서 밀리초까지 비교한다. 화면의 시각 표시는 초 단위이고 원문·정밀 시각은 API 기록에 보존한다. 사유는 세 종류의 최소 분류만 받으며 상세 건강·상담 메모 입력란은 없다.

명단은 열린 화면에서 통상 1초 간격으로 조회하고, 버튼 작업 뒤 즉시 갱신한다. 브라우저 절전·백그라운드 제한·프로세스 중단 등에 따른 지연이 있으므로 정확한 시각의 운영 알림을 보장하지 않는다. 18:25는 미확인 검토 시작일 뿐 접수 마감이 아니다. 연결이 끊기면 오래된 명단으로 판단하지 말라는 경고를 표시한다.

## 접근 범위와 미완료

서버는 `127.0.0.1`에만 연결한다. 허용한 Host·Origin을 검사하고 변경 요청에 같은 Origin, JSON 형식, 별도 요청 헤더와 현재 연습 ID를 요구한다. 다른 출처 허용(CORS)과 외부 스크립트는 사용하지 않는다. 고정 가상 명단 밖 ID, 클라이언트가 지정한 인식 시각·확인자, 상세 메모, 큰 입력을 거부한다. 확인 충돌·이전 연습의 요청은 409로 거부해 최신 명단에서 다시 검토하게 한다. 연습 ID는 실제 사용자 인증 수단이 아니다.

이 제한은 학교 운영용 계정 인증·역할 권한이 아니다. 같은 노트북의 프로세스는 데모에 접근할 수 있다. `DEMO_OPERATOR`는 고정 가상 기록자일 뿐 실제 신원을 확인하지 않는다. 서버 공개·포트 전달·실제 데이터 입력은 범위 밖이다. 학교 승인·동의·대체 출석·담당자 로그인·권한·보유기간·삭제·센서와의 신뢰 가능한 연결을 검증하기 전까지 실제 운영에 사용하지 않는다.
