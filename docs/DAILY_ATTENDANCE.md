# 하루 한 건 출석 저장 — 로컬 합성 데이터 검증

구현·테스트·실행·문서화: **Codex AI assistant**, 2026-11-18 KST. 사용자의 AI 구현 요청과 후속 계속 지시에 따른 작업이다. 학생 독립 구현, 실제 지문 인식, 학교 배포 성과로 계산하지 않는다.

## 구현한 동작

- `src/daily-attendance.mjs`가 SQLite 파일에 `(한국 시간 날짜, 가명 학생 ID)`별 한 건을 저장한다. 학생 ID는 영문·숫자로 시작하는 1~64자 영문·숫자·밑줄·하이픈 식별자다. 이 형식 검사는 등록된 학생인지 확인하는 기능이 아니다.
- 시각은 공통 `src/timestamp.mjs`에서 검증하고 `Asia/Seoul` 기준으로 날짜와 시각을 구한다. 실행 컴퓨터의 로컬 날짜나 입력 문자열 앞부분을 날짜 키로 쓰지 않는다.
- 해당 날짜의 최초 **수락된** 인식이 기록을 생성한다. 같은 날짜의 재인식·재전송은 새 행을 만들거나 최초 시각·상태를 바꾸지 않는다. 늦게 도착한 과거 시각 이벤트도 자동으로 최초 기록을 덮어쓰지 않으며, 정정은 후속 기능이다.
- 원 출석 행은 18:25 정각까지 `present`, 그 이후 `review_required`로 저장한다. 후자는 확정 지각이 아니다. 이후 구현한 [명단·사유 API](ROSTER_REVIEW.md)가 별도 확인 이력으로 면제 여부를 표시하며 원 행·인식 시각은 유지한다.
- 한국 시간 자정에 새 날짜가 시작된다. 그 이후 첫 인식은 새 날짜의 기록을 만들며 전날 출석을 보충하지 않는다. 새벽과 늦은 밤에도 당일 첫 인식을 받는다.
- 입력된 원 시각 문자열과 같은 순간의 UTC 시각을 함께 보존한다. 반환 객체를 호출자가 바꿔 저장 내용을 변경할 수 없도록 한다.
- SQLite 기본 키와 충돌 시 무처리를 사용해 같은 파일에 동시 요청이 와도 한 건만 생성한다. 첫 수락은 가장 이른 기기 시각이 아니라 데이터베이스가 먼저 수락한 요청을 뜻한다.
- 조회만으로 결석 행을 만들지 않는다. 아직 명단·면제·외출 정보가 없으므로 기록이 없는 학생의 상태를 이 모듈이 판정하지 않는다.

## 실행과 파일

검증 환경: Node.js v24.22.1의 내장 SQLite 3.53.4. 외부 패키지를 설치하지 않았다. Node의 `node:sqlite`가 있는 실행 환경이 필요하며 다른 버전·운영 환경까지 검증했다고 주장하지 않는다.

```powershell
node scripts/demo-attendance.mjs
```

이 명령은 **가상 학생 S001과 고정 합성 시각**으로 데모를 실행한다. 파일은 `local/synthetic-attendance/demo.sqlite`에 남고 Git에서 제외된다. 이미 데모를 실행한 경우 기존 기록을 사용하므로 다시 실행해도 같은 날짜의 기록이 늘어나지 않는다. 프로그램을 닫았다 다시 실행해도 파일 기록은 유지된다. 실제 학생 명단·지문·특징정보·사유를 이 데모에 넣지 않는다.

API는 `openAttendanceStore(databasePath)`의 `recordCheckIn({studentId, recognizedAt})`, `getAttendance({studentId, attendanceDate})`, `listForDate(attendanceDate)`, `close()`다. `created`는 새 행 생성 여부이고 `record`는 보존된 최초 기록이다. 저장할 부모 폴더는 호출자가 준비한다. 저장 가능한 한국 날짜의 연도는 0001~9999이며, 지원 범위 밖은 오류로 처리한다.

`':memory:'`는 테스트용으로만 사용하며 종료 시 사라진다. 실제 파일 경로를 넘긴 경우만 재시작 후 유지된다. 데이터베이스와 저널·WAL·SHM 파일은 Git에서 제외했다.

## 실제 확인 결과

```powershell
node --test --test-reporter=tap practice/task-001a.test.mjs practice/task-001a.validation.test.mjs test/daily-attendance.test.mjs
```

**89개 통과, 실패 0개**: 기존 시각 검사 67개와 새 저장소 검사 22개다. [결과·소스 해시](../evidence/daily-attendance-01/result.json), [최종 실행 출력](../evidence/daily-attendance-01/run-03.tap). 실패 시에도 테스트 자원이 닫히도록 정리 코드를 보완한 뒤 최종 재실행했다. 이전 성공 출력 run-02.tap도 보존한다.

새 검사는 최초 기록·원 시각 보존, 반복·순서 역전 인식, 한국 자정 전후, 정각과 밀리초 경계, 시각 제한 없음, 잘못된 입력의 미저장, 학생별 분리, 조회·반환값 보호, 파일 재개방, 네 프로세스의 동시 접근을 포함한다. 동시성 검사는 특정 로컬 파일의 네 요청 한 건이며 실제 학교 규모의 부하·장애 복구 검증은 아니다.

첫 실행에서는 날짜 포맷터의 ISO 달력이 이 런타임에서 연호 필드를 생략해 유효 날짜를 거부하는 **AI 구현 결함**이 발견됐다(88개 중 17개 실패). 명시적인 그레고리력·연호 처리로 수정하고 범위 밖 연도 검사를 추가했다. [실패 원문과 원인](../evidence/daily-attendance-01/failed-01.json)을 보존했으며 학생의 발견으로 주장하지 않는다.

실제 데모에서 S001의 11월 18일 18:20 첫 인식은 생성, 같은 날 20:00 인식은 중복, 11월 19일 18:26 인식은 새 날짜의 확인 필요 기록으로 나타났다. [데모 관찰](../evidence/daily-attendance-01/demo-result.json). 미래 날짜도 테스트용 고정 입력이지 실제 출석 기록이 아니다.

## 근거와 남은 범위

[Node.js 공식 SQLite 문서](https://nodejs.org/api/sqlite.html)의 준비된 질의와 [SQLite 공식 UPSERT 설명](https://www3.sqlite.org/lang_UPSERT.html)의 유일성 충돌 처리를 참고했고, 사용한 기본 API는 현재 Node 24 환경에서 직접 확인했다. 새로운 중복 방지 알고리즘을 발명한 것은 아니다.

현재 미확인 명단 조회·최소 사유 확인·지각 면제·확인 이력 API와 별도 가상 시계·자동 갱신 화면을 연결했다. 화면의 합성 기록·시계를 재시작 후 복원하는 검사를 포함한 141개에 상황 확인용 알림 미리보기 11개를 추가해 전체 152개가 통과했다. [API 설명](ROSTER_REVIEW.md), [현재 화면·저장·검증 한계](LOCAL_DEMO.md), [미리보기 범위](NOTIFICATION_PREVIEW.md). 실제 등록 학생 명단, 담당자 인증·역할 권한, 운영용 백업·보유기간·삭제, 실제 서버 운영·센서·알림 전송은 없다. 입력 시각은 호출자가 제공하는 검증된 형식의 값이며 신뢰할 수 있는 장치·서버 시계인지 인증하지 않는다. 가상 시계 저장은 실제 운영 시각의 인증이 아니며 이 모듈만으로 학교 운영 승인이 갖춰진 것이 아니다.
