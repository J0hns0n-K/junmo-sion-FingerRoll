# 상황 확인용 알림 미리보기

2026-11-20 AI 구현·검사. 합성 ID·가상 시각만 사용하며 학생 독립 구현이나 실제 사생회 알림 운영의 증거가 아니다.

## 화면에서 확인하기

[로컬 화면 실행](LOCAL_DEMO.md) 후 명단 아래의 ‘알림 미리보기 → 미리보기 열기’를 누른다. 열린 문안은 명단과 같은 조회 시점으로 갱신된다. 수신자는 지정하지 않으며 전송 버튼·외부 메시지 연결·예약 전송은 없다.

1. 가상 시계가 18:25 전이면 검토 시작 안내만 표시하며 후보 ID·문안을 만들지 않는다. 출석 접수는 계속 가능하다.
2. S001을 정상 출석시키고 S002의 사유만 확인한다. 시계를 1분 앞으로 옮기면 S003·S004가 상황 확인 후보가 된다.
3. S003이 늦게라도 출석하면 지각 여부 확인 상태와 별개로 이 문안에서 제외된다. 지각 확인용 통보를 추가 생성하지 않는다.
4. S004의 사유를 확인하면 문안을 비우고 미확인 후보가 없다고 표시한다. 사유 확인만으로 출석 건수를 늘리지는 않는다.
5. S004의 사유 확인을 취소하면 원래 확인 이력은 남고 다시 상황 확인 후보가 된다.

18:25는 미확인 명단의 검토 시작이다. 알림의 최종 검토·전송 시각은 확정하지 않았으며, 미리보기가 열렸다고 전송이 승인된 것도 아니다. 하루 전체 출석 접수와 별개다. 2·3교시에 별도 출석 의무·미출석 알림을 만들지 않는다.

## 문안과 최소 정보

문안의 목적은 **상황 확인 요청**이다. 출석 기록도 확인된 사유도 없는 학생만 후보로 다루고 결석으로 확정하지 않는다. 학생이나 사감 선생님을 통해 누락 출석·전달받은 사유·인식 장애 여부를 확인해야 한다는 안내를 포함한다.

| 포함 | 제외 |
|---|---|
| 합성 날짜·1교시 맥락, 미확인 가상 ID, 검토·미전송 표시 | 정상·늦은 출석·면제 학생의 ID와 인식 시각 |
| 제외된 출석 학생 수·사유 확인 대기 학생 수의 별도 화면 집계 | 사유 확인 학생의 ID·사유 종류·담당자·상세 건강·상담 내용 |

집계는 문안 외 화면에 표시한다. 후보가 없을 때는 빈 메시지(`null`)를 반환한다. 연결이 끊기면 기존 문안을 비우고 미리보기 버튼을 비활성화한다. 이는 메시지 발송 성공이나 결석의 근거가 아니다. 기존 합성 출석·사유는 바꾸지 않는다.

## 구현 범위

`src/notification-preview.mjs`가 이미 검증된 명단 스냅샷에서 문안을 읽기 전용으로 만든다. `/api/state` 응답의 `notificationPreview`는 명단과 같은 날짜·조회 시각을 사용한다. 다음 필드를 제공한다.

- `previewOnly: true`, `deliveryEnabled: false`, `recipient: null`, `requiresHumanReview: true`
- `kind: 'whereabouts_check'`, `phase: 'before_review' | 'review_required' | 'nothing_to_check'`
- 후보 가상 ID·최소 집계·문안. 출석·사유 상세 행과 확인자 ID는 포함하지 않음

미리보기 자체는 출석·확인 이력·알림 큐를 저장하지 않는다. 반복 조회해도 추가 출석·사유 이력이 생기지 않는다. 기존 데모는 가상 시계 체크포인트를 저장한다. 실제 발송 경로 `/api/send`는 없으며 요청은 404로 거부한다. 발송 재시도·수신자 승인·발송 감사 이력·중복 전송 방지는 아직 구현·검증하지 않았다.

화면의 통상 1초 조회는 운영용 정시 실행 보장이 아니다. 담당자 로그인·역할 권한·학교 승인·수신자 확인·동의·대체 출석·보유기간·삭제와 실제 전송 승인은 여전히 준비 대상이다. 이 합성 프로토타입에 실제 학생 정보를 입력하지 않는다.
