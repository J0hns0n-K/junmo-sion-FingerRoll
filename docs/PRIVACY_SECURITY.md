# 개인정보·동의·보안 검토

2026-11-16 기준 AI가 공식 자료를 확인해 작성한 **설계 제안**이다. 특정 학교 운영의 법적 적합성을 확정한 문서나 동의서가 아니다. 실제 참여 연령, 학교 정책, 처리 책임자와 근거를 학교 개인정보 담당자가 검토해야 한다.

## 확인한 공식 근거

- 특정 개인 식별 목적으로 기술적으로 생성된 신체·생리·행동 특징정보는 민감정보 범위에 포함된다. 지문 특징정보를 일반 출석 데이터와 동일하게 취급하지 않는다. [개인정보 보호법 시행령 제18조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034050143)
- 민감정보 처리는 다른 개인정보 처리와 구분한 별도 동의 또는 이를 요구·허용하는 법령 근거와 안전성 확보조치가 필요하다. 학교 승인만으로 필요한 동의를 대체한다고 가정하지 않는다. [개인정보 보호법 제23조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335227)
- 만 14세 미만에 대해 이 법상 동의가 필요한 개인정보 처리를 하는 경우 법정대리인 동의와 확인이 필요하다. 모든 미성년자에게 일률적인 법정대리인 동의 요건이 적용된다고 쓰지 않는다. 학교의 추가 절차는 별도로 확인한다. [제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398521)
- 추가 검토 자료: 개인정보위 [생체정보 보호 안내서(2024.12.) 게시물](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20781). 게시물은 확인했으나 첨부 PDF 전체를 검토했다고 주장하지 않는다.

## 실제 데이터 사용 전 통과할 게이트

| 게이트 | 설계·검증 조건 | 현재 상태 |
|---|---|---|
| G0 합성 데이터 | 가상 학생 ID·시간으로만 개발. 실제 명단·지문·동의서·연락처·대응표를 Git에 넣지 않음 | 합성 출석 저장·명단 API·노트북 화면 구현; 실제 데이터 미사용 |
| G1 운영 승인·동의 | 학교 책임자·목적·항목·접근자·보유기간·거부/철회 절차 확정. 적법한 처리 근거와 필요한 별도 동의·연령별 절차 검토 | 미확정 |
| G2 대체 출석 | 지문 거부·철회·부상·인식 실패 시 수기 확인/카드 등 동등한 경로. 거부로 자동 결석·지각 또는 불이익을 주지 않음 | 미구현 |
| G3 장치 보안 | 센서 내부 매칭을 우선 검토. 데이터시트와 실험으로 특징정보 저장·암호화·내보내기·삭제·분실 위험 확인 | AS608 보유(2026-11-17 사용자 보고); 실물 사양·보안 기능 검증 대기 |
| G4 접근·삭제 | 특징정보, 가명 ID 대응표와 출석 기록 분리; 최소 권한·인증·통신 보호·비밀키 분리·접근 기록. 보유기간, 철회/목적 종료/폐기 시 센서·앱·백업 삭제 검증 | 미구현 |
| G5 미출석·알림 | 기록 없음은 미확인. 학생들이나 사감 선생님을 통한 상황 파악과 최종 통보를 구분. 외출 복귀 직후 출석은 확인 후 지각 제외하고, 외출 중·확인 대기를 결석으로 통보하지 않음. 예외·장애·대체 출석 검토 후 담당자가 확정. 사생회 수신 권한과 최소 정보·채널을 학교가 승인. 초기에는 실제 전송 없는 미리보기만 | 합성 명단·최소 사유 이력·면제 API와 로컬 화면 구현; 인증·학교 권한·실제 알림 미구현·전송 없음 |

센서 내부 저장이나 가명 ID만으로 익명·안전·법적 적합성이 확보되는 것은 아니다. GitHub Private 설정도 개인정보를 저장해도 된다는 허가가 아니다. `.gitignore`는 보조 장치이므로 모든 커밋의 실제 내용을 확인해야 한다.

## 실패와 오용에 대비할 사항

- 오인식·미인식·기기 중단·잘못된 시각을 결석의 근거로 자동 확정하지 않는다. 정정·이의 제기와 담당자 확인 경로를 제공한다.
- 담당자는 필요한 날짜·교시·대상자만 조회한다. 사생회에 전체 출석 이력, 지문·특징정보·매칭 점수나 불필요한 연락처를 전달하지 않는다.
- 외출 확인에는 필요한 사유 구분·확인 여부·담당자 이력만 기록하는 방향으로 설계한다. 상세 외출 목적·친구의 진술 전체·정밀 위치를 불필요하게 수집하지 않는다. 출석 지문을 위치 추적 용도로 확대하지 않는다.
- 사용자가 전달받은 개인 사유는 ‘사유 확인’과 처리 결과 중심으로 관리한다. 건강 증상의 상세 설명이나 사감 선생님과의 상담 내용은 출석 시스템·Git에 남기지 않는다. 사유가 확인됐어도 실제 출석 여부와 별도로 표시한다.
- 실제 알림은 승인된 수신자와 목적이 확인된 뒤 명시적 전송 승인 하에 수행한다. 이 프로젝트 킥오프는 다른 사람에게 메시지를 보낼 권한을 부여하지 않는다.
- 특징정보를 단순 해시하면 안전하다는 설계를 채택하지 않는다. 실제 센서의 저장·삭제 능력과 접근 통제를 확인한 뒤 구조를 정한다.
- 동의서·학생 데이터는 학교가 승인한 별도 저장 장소에서 다룬다. 저장소에는 합성 예시와 검증 절차만 남긴다. 유출 의심 시 수집·전송을 중지하고 학교 책임자에게 연결한다.
