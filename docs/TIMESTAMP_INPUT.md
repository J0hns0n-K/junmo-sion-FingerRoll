# 시각 입력 검증 — 2026-11-18

이 입력 검증과 추가 회귀 테스트는 사용자 요청으로 AI가 작성했다. 이전 안내 연습 소스와 변경 전 검사는 `evidence/task-001a-strict-input-01/`에 보존한다. 학생 독립 구현·센서 실험 성과로 계산하지 않는다.

## 해결한 문제

기존 `new Date(value)` 방식은 숫자 0, 불리언 true, 시간대가 없는 문자열, 존재하지 않는 2026-02-29를 거부하지 않았다. 출석 판정에 들어오기 전에 입력 타입·형식·달력을 명시적으로 검사하도록 바꿨다. 테스트 파일에 추가돼 있던 독립된 `ㄹ` 한 글자도 수정 전 원문을 보존한 뒤 제거했다. 기존 세 테스트의 입력·예상값은 변경하지 않았다.

## 이 프로젝트가 받는 형식

```text
YYYY-MM-DDTHH:mm:ss[.소수초](Z 또는 +HH:mm 또는 -HH:mm)
```

- 문자열만 받는다. 연도는 0000~9999의 네 자리, 초까지 필수, 소수초는 생략하거나 1~3자리다.
- 날짜가 실제 달력에 존재해야 한다. 윤년과 월별 날짜 수를 확인한다.
- 시각은 00:00:00~23:59:59 범위이며, 시간대가 반드시 있어야 한다. 오프셋 시는 00~23, 분은 00~59다. 숫자 오프셋을 해석하며 실제 지명 시간대의 존재 여부를 검사하는 기능은 아니다.
- 앞뒤 공백·개행, 숫자·배열·객체, 날짜만 있는 값, 시간대 누락, 달력 오류는 거부한다.
- 이 형식은 프로젝트가 선택한 제한된 입력 형식이다. 모든 ISO 8601 표현을 지원한다고 주장하지 않는다. 예를 들어 24:00, 확장 연도와 소수초 네 자리 이상은 받지 않는다.

예: `2026-11-17T18:25:00+09:00`과 `2026-11-17T09:25:00Z`는 같은 순간이다. 문자열 순서가 아닌 검증·변환된 시각을 비교한다. 정각은 false, 시작 이후는 true다. true는 사유 확인 대상이며 최종 지각 확정이 아니다.

[ECMAScript 2026 Date 설명](https://tc39.es/ecma262/2026/multipage/numbers-and-dates.html#sec-date-time-string-format)은 시간대 없는 날짜·시간 문자열을 실행 환경의 로컬 시간으로 해석할 수 있고, 비표준 입력에 구현별 처리가 가능함을 설명한다. 이 프로젝트는 위의 명시적 형식만 허용해 그런 자동 해석을 피한다. 달력 검사는 문자열 정규화 전에 별도로 수행한다.
