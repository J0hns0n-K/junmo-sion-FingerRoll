# 출석 설계와 검증 계획

**AI가 작성한 제안이며, 동작하는 출석 시스템은 아직 없다.** 교시 시각은 사용자가 제공했으며, 참여자, 예외 규칙과 실제 하드웨어는 미확정이다.

## 사용자 제공 시간표

2026-11-16 대화에서 사용자가 제공한 야자 시간표다. 저녁 시각으로 해석해 `Asia/Seoul`의 24시간제로 기록했다. 학교 공식 문서를 별도로 검증한 것은 아니다.

| 교시 | 시작 | 종료 | 길이 |
|---|---|---|---|
| 1교시 | 18:25 | 19:20 | 55분 |
| 2교시 | 19:30 | 20:20 | 50분 |
| 3교시 | 20:30 | 21:20 | 50분 |

교시 사이에는 각각 10분 휴식이 있다. 적용 요일·날짜·시간표 예외는 아직 정하지 않았다.

## 초기 범위 — 시각 제한 없는 하루 한 건 출석

사용자 최신 요구는 **언제든 하루 한 번 출석할 수 있게 하는 것**이다. 학생별 날짜별 출석·지각·미확인 명단과 그 범위의 알림만 설계한다. 하루는 `Asia/Seoul` 기준 해당 날짜 00:00 이상, 다음 날짜 00:00 미만이다. 2·3교시는 시간표 참고 정보이며 별도 출석 의무·미출석 상태·알림을 생성하지 않는다. 그 시간의 첫 인식도 해당 날짜의 지각으로 기록한다. 하루 한 번의 출석을 야자 전 시간의 재실 확인으로 간주하지 않는다.

이 결정은 이전의 18:10 접수 시작 제한을 대체한다. **해당 날짜 18:25 정각까지 정상 출석, 그 이후 첫 인식은 지각**이다. 시각 때문에 당일의 첫 출석을 거부하지 않는다. 첫 유효 인식으로 만든 기록은 재인식으로 추가 생성하거나 시각·상태를 덮어쓰지 않는다. 담당자 정정은 별도 감사 이력으로 관리한다. 자정을 넘긴 인식은 새 날짜의 기록 대상이며 전날 출석을 자동 보충하지 않는다.

## 처리 경계

1. **식별 어댑터**: 센서 내부 매칭 가능성을 검토하고 앱에는 가명 학생 ID와 성공/실패 결과만 전달한다. 원본 지문 이미지나 특징정보를 앱·GitHub로 내보내지 않는 구조를 우선 검토한다. 장치 사양 확인 전 지원 기능으로 단정하지 않는다.
2. **시간 판정**: 학교가 승인한 서버/기기 시계와 `Asia/Seoul` 기준 1교시 시작 18:25를 사용한다. 단말 시각 오류·오프라인 재전송은 검토 대상으로 남긴다. 수신 시각과 인식 시각의 차이를 기록하고 지연 이벤트의 처리 정책을 정한다.
3. **출석 기록**: `(한국 시간 날짜, 가명 학생 ID)`를 논리적 유일 키로 사용한다. 같은 날짜의 첫 유효 인식만 출석 기록을 생성하며 중복 스캔·재전송·동시 요청에도 한 건만 유지하도록 설계한다. 첫 기록은 정상 재인식으로 변경하지 않는다. 오프라인·신뢰할 수 없는 기기 시각은 별도 검토 대상이다.
4. **명단 조회**: 해당 날짜의 야자 참여 대상에서만 명단을 구성한다. 외출·면제·수기 확인·정정 이력을 반영하고, 권한 있는 담당자가 필요한 날짜의 명단만 조회한다.
5. **알림 큐**: 기본은 미리보기. 확인 시점은 아직 정하지 않았고 하루 종일 출석을 받는 것과 별개다. 검토 시점에 기록이 없더라도 이후 첫 인식은 지각으로 접수하고 명단·미전송 알림을 갱신한다. 검토 시점·담당자 확인·승인된 수신자가 정해진 뒤 최소 정보로 보내는 후속 기능이다. 이번 세션에서는 실제 메시지를 보내지 않는다.

## 확정 규칙과 미확정 정책

| 항목 | 상태·제안 |
|---|---|
| 정각/지각 | 해당 한국 날짜 18:25까지 정상 출석, 이후 첫 인식은 지각 |
| 사전 인식 | 시각 제한 없음. 18:10 이전도 당일 첫 유효 인식이면 정상 출석. 과거 15분 제한은 폐기 |
| 출석 접수 구간 | 한국 시간의 달력 날짜 전체. 매일 00:00에 날짜가 바뀌며 별도 접수 마감 시각을 두지 않음 |
| 다음 날 인식 | 다음 날 출석 대상으로 판정. 전날 출석을 자동 보충하지 않음 |
| 중복 인식 | 정상 재시도로 출석을 추가 생성하거나 최초 정시 출석을 지각으로 덮어쓰지 않음. 원 이벤트와 정정은 감사 가능하게 구분 |
| 미출석 | 확인 시점 전 `미확인`. 이후에도 면제·외출·대체 출석·장애를 확인해야 함 |
| 센서 실패·정전·시계 오류 | 결석으로 자동 확정하지 않음. 수기/대체 확인과 정정 경로 제공 |
| 알림 | 학교가 사생회 수신 범위·권한을 승인해야 실제 전송 가능. 전송 재시도에도 동일 알림이 중복되지 않도록 키·전송 상태 관리 |

## 검증 순서

| 단계 | 필요한 사례 | 인정할 수 있는 증거 |
|---|---|---|
| 001A 경계 비교 | 직전·정각·직후, 시간대 동치, 오류 | 학생 함수·테스트·출력 |
| 001B 날짜 판정 | 한국 날짜의 자정 경계·UTC 날짜 차이, 2·3교시 별도 출석 의무·미출석 알림 미생성 | 합성 시각과 기대 결과 |
| 002 출석 저장 | 중복 스캔·재전송·동시 요청·순서 역전·다음 날짜, 최초 시각·상태 유지 | 날짜·학생 유일 키와 상태 전이 테스트 |
| 003 명단·미확인 | 대상자 누락, 면제, 수기 정정, 장치 장애 | 합성 명단 대조; 실제 학생 결석 추정 금지 |
| 004 알림 미리보기 | 승인 전 차단, 최소 정보, 재시도 중복, 잘못된 수신자 | 실제 전송 없는 미리보기·권한 테스트 |
| 005 센서 실험 | 인식 실패·오인식·삭제·분실·오프라인 | 장치 모델·조건·반복 수·실패 원자료. 모의 결과와 분리 |

실제 센서·승인·동의가 없는 경우 단계 005와 학교 파일럿을 완료로 표시하지 않는다. 인식률·시간 절감·도입 인원 수는 실제 실험 전 기록하지 않는다.
