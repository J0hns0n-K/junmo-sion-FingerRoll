# 출석 설계와 검증 계획

**AI가 작성한 제안이며, 동작하는 출석 시스템은 아직 없다.** 교시 시각은 사용자가 제공했으며, 참여자, 예외 규칙과 실제 하드웨어는 미확정이다.

## 사용자 제공 시간표

2026-11-16 대화에서 사용자가 제공한 야자 시간표다. 저녁 시각으로 해석해 `Asia/Seoul`의 24시간제로 기록했다. 학교 공식 문서를 별도로 검증한 것은 아니다.

| 교시 | 시작 | 종료 | 길이 |
|---|---|---|---|
| 1교시 | 18:25 | 19:20 | 55분 |
| 2교시 | 19:30 | 20:20 | 50분 |
| 3교시 | 20:30 | 21:20 | 50분 |

교시 사이에는 각각 10분 휴식이 있다. 적용 요일·날짜·시간표 예외는 아직 정하지 않았다.

## 초기 범위 — 1교시 한 번 출석

사용자는 초기 버전에서 처음 시작하는 1교시만 출석 확인하기로 범위를 줄였다. 날짜별 1교시 출석·지각·미확인 명단과 그 범위의 알림만 설계한다. 2·3교시는 시간표 참고 정보로만 남기고 출석 대상·미출석 상태·알림을 생성하지 않는다. 1교시 출석을 2·3교시 재실 확인으로 간주하지 않는다.

사용자는 지문 인식에 의한 출석 접수를 시작 15분 전부터 받기로 정했다. 따라서 **18:10 정각부터 18:25 정각까지 정상 출석**, **18:25 이후 유효한 접수 구간의 인식은 지각**이다. 18:10 이전 인식은 출석으로 기록하지 않는다. 접수 마감 시각, 마감 정각 인식 처리와 미출석 확인 시점은 미정이다. 접수 마감을 19:20으로 자동 설정하거나, 그날의 모든 늦은 인식을 무제한 출석으로 인정하지 않는다. 교시별 반복 출석은 이후 사용자 결정이 있을 때 확장한다.

## 처리 경계

1. **식별 어댑터**: 센서 내부 매칭 가능성을 검토하고 앱에는 가명 학생 ID와 성공/실패 결과만 전달한다. 원본 지문 이미지나 특징정보를 앱·GitHub로 내보내지 않는 구조를 우선 검토한다. 장치 사양 확인 전 지원 기능으로 단정하지 않는다.
2. **시간 판정**: 학교가 승인한 서버/기기 시계와 `Asia/Seoul` 기준 1교시 시작 18:25를 사용한다. 단말 시각 오류·오프라인 재전송은 검토 대상으로 남긴다. 수신 시각과 인식 시각의 차이를 기록하고 지연 이벤트의 처리 정책을 정한다.
3. **출석 기록**: `(학사 날짜, 교시 ID=1, 가명 학생 ID)`를 논리적 유일 키로 사용한다. 교시 ID는 1로 고정하며 초기 버전에서 다른 교시 기록을 만들지 않는다. 재인식·재전송은 같은 날짜의 출석을 중복 생성하지 않도록 설계한다.
4. **명단 조회**: 해당 날짜의 1교시 참여 대상에서만 명단을 구성한다. 외출·면제·수기 확인·정정 이력을 반영하고, 권한 있는 담당자가 필요한 날짜의 명단만 조회한다.
5. **알림 큐**: 기본은 미리보기. 확인 시점 후 담당자가 검토한 미출석 건만 승인된 수신자에게 최소 정보로 보내는 후속 기능이다. 이번 세션에서는 실제 메시지를 보내지 않는다.

## 확정 규칙과 미확정 정책

| 항목 | 상태·제안 |
|---|---|
| 정각/지각 | 사용자 요구: `인식 시각 > 시작 시각`이면 지각, 같으면 지각 아님. 유효한 출석 허용 구간 안에서만 적용 |
| 사전 인식 | 사용자 결정: 시작 15분 전인 18:10 정각부터 허용. 그 이전에는 출석을 기록하지 않음. 학교 운영 승인과는 별개의 요구사항 결정 |
| 출석 접수 구간 | 날짜와 1교시를 명시. 시작 18:10, 마감은 미정이며 다른 교시에 자동 배정하지 않음 |
| 접수 마감 이후 인식 | 자동 출석 인정하지 않음. 마감과 예외 정책 확정 필요 |
| 중복 인식 | 정상 재시도로 출석을 추가 생성하거나 최초 정시 출석을 지각으로 덮어쓰지 않음. 원 이벤트와 정정은 감사 가능하게 구분 |
| 미출석 | 확인 시점 전 `미확인`. 이후에도 면제·외출·대체 출석·장애를 확인해야 함 |
| 센서 실패·정전·시계 오류 | 결석으로 자동 확정하지 않음. 수기/대체 확인과 정정 경로 제공 |
| 알림 | 학교가 사생회 수신 범위·권한을 승인해야 실제 전송 가능. 전송 재시도에도 동일 알림이 중복되지 않도록 키·전송 상태 관리 |

## 검증 순서

| 단계 | 필요한 사례 | 인정할 수 있는 증거 |
|---|---|---|
| 001A 경계 비교 | 직전·정각·직후, 시간대 동치, 오류 | 학생 함수·테스트·출력 |
| 001B 1교시 접수 범위 | 다른 날짜·접수 시작/마감 경계·미설정 구간, 2·3교시 출석 의무·미출석 알림 미생성 | 합성 시각과 기대 결과 |
| 002 출석 저장 | 중복 스캔·재전송·순서 역전·다음 날짜, 교시 ID 1 고정 | 유일 키와 상태 전이 테스트 |
| 003 명단·미확인 | 대상자 누락, 면제, 수기 정정, 장치 장애 | 합성 명단 대조; 실제 학생 결석 추정 금지 |
| 004 알림 미리보기 | 승인 전 차단, 최소 정보, 재시도 중복, 잘못된 수신자 | 실제 전송 없는 미리보기·권한 테스트 |
| 005 센서 실험 | 인식 실패·오인식·삭제·분실·오프라인 | 장치 모델·조건·반복 수·실패 원자료. 모의 결과와 분리 |

실제 센서·승인·동의가 없는 경우 단계 005와 학교 파일럿을 완료로 표시하지 않는다. 인식률·시간 절감·도입 인원 수는 실제 실험 전 기록하지 않는다.
