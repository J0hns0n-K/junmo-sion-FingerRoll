# FingerRoll project rules

- Follow the current fingerprint evening-study attendance scope. The imported RoboMetrics grid-planning scaffold is AI reference material for a different domain.
- Initial scope: one check-in for period 1, which starts at 18:25 Asia/Seoul. Check-in opens at 18:10 inclusive (15 minutes before class); earlier scans must not register attendance. 18:25 exactly is on time; later eligible scans are late. Closing time remains undecided. Periods 2 and 3 are timetable context only; do not create attendance obligations or absent notifications for them. Any later expansion needs a new user decision.
- Keep AI reference imports, AI-authored changes and verified student-authored work distinguishable in commits and docs/CONTRIBUTION_LOG.md. Git account identity or commit count alone does not establish student authorship.
- Do not complete a task reserved for student implementation unless the user explicitly asks for AI implementation; label any resulting AI code accurately.
- Preserve source archives and historical evidence. Record source revision, inputs, command, actual result, operator and limitations for each run. Synthetic software results are not sensor or deployment evidence.
- Keep original handoffs, private school/admissions links, real student rosters, biometrics, mapping tables, consent forms, credentials and device/database dumps out of Git, including private GitHub repositories.
- Use synthetic fixtures until school governance, lawful basis/consent, alternatives, access, retention and deletion have been reviewed. Outbound absence notifications default to preview only and require explicit authorization before actual sending.
- Human review and a correction path precede attendance consequences. A failed scan or outage is not evidence of absence.
- Preserve unrelated changes. Update README and claim/evidence records when verified status changes; do not invent results, authors or dates.
